Phase 1: Lexical Analysis (Scanning & Tokenization)

Phase 1 of 6

The lexical analyzer scans the stream of C source characters and groups them into meaningful language units called Tokens. Tokens include keywords, identifiers, constants, string literals, operators, and punctuation. Comments and whitespaces are stripped.

Producing Tool: c-visualize-lexer (ISO C23 Tokenizer) • Click any token below to highlight its exact source position in Monaco.

Phase 2: Syntax Analysis (Parsing & AST Generation)

Phase 2 of 6

The syntax analyzer checks whether the tokens satisfy the formal grammar of the C language, generating a hierarchical Abstract Syntax Tree (AST). The AST establishes operator precedence, nested scopes, and statement structure.

Producing Tool: c-visualize-ast-engine (ISO C Frontend) • Click any tree node to highlight its source code range in Monaco.

Abstract Syntax Tree will be generated upon compilation.

Phase 3: Semantic Analysis & Symbol Table

Phase 3 of 6

The semantic analyzer verifies type compatibility, identifier scoping, function argument counts, and variable declarations. It constructs Symbol Tables that record type, scope lifetime, and memory characteristics of all identifiers.

Producing Tool: c-visualize-symbol-engine & GCC Semantic Diagnostic Checker

Phase 4: Intermediate Code Generation (GCC GIMPLE IR)

Phase 4 of 6

The compiler lowers the high-level C AST into an intermediate representation called GIMPLE. In GIMPLE, complex nested expressions are decomposed into 3-Address Code instructions using temporary variables (D.xxxx).

Producing Tool: Authoritative GCC -fdump-tree-gimple Dump Facility
GCC -fdump-tree-gimple
Compile a C program to inspect genuine GCC GIMPLE IR.

Phase 5: Code Optimization (GCC Optimization Passes)

Phase 5 of 6

Optimization passes transform intermediate code into a more efficient form without altering program semantics. Techniques include Constant Folding, Dead-Code Elimination, Static Single Assignment (SSA), and Basic Block Restructuring.

Producing Tool: GCC Optimization Pipeline (-O0 vs selected -O1/-O2/-O3 -fdump-tree-optimized)

Compile code to compare unoptimized vs optimized GIMPLE artifacts.

Phase 6: Target Code Generation (x86_64 Assembly)

Phase 6 of 6

The code generator maps intermediate representations into machine-level assembly instructions for the target CPU architecture. It assigns CPU registers (%rax, %rbp, %rsp), manages stack frames, and emits machine instructions (movl, pushq, call).

Producing Tool: GCC -S -fverbose-asm (GNU Assembler)
Actual GCC target and compiler version appear after compilation.
Compile code to generate target assembly from GCC.

Supporting Stage: Preprocessing

Build Stage

Before lexical analysis begins, the C preprocessor handles all directives beginning with #. It recursively inserts header files (#include), replaces symbolic constants (#define), and evaluates conditional directives (#ifdef).

Producing Tool: GCC Preprocessor (gcc -E -dD)

Supporting Stage: Linking

Build Stage

After target code generation produces machine object files, the Linker resolves external symbol references (such as printf or malloc) against C runtime libraries and bundles everything into the final standalone executable binary.

Producing Tool: GNU ld (Invoked via GCC Toolchain)
Compile code to inspect linker status and library resolution.
